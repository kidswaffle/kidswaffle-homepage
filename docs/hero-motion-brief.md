# 키즈와플 첫 화면 모션그래픽 제작 지시서 (A+B 함께)

작성일 2026-10-14 · 대상 사이트 https://www.kidswaffle.com · 저장소 `kidswaffle/kidswaffle-homepage`

이 문서는 첫 화면(히어로) 도입 모션을 **한 번 설계해서 두 곳에 쓰는** 작업의 지시서입니다.

- **A. 홈페이지 코드 모션**: 첫 화면에서 바로 움직이는 인라인 모션 (사이트 코드)
- **B. Remotion 영상**: 같은 장면을 MP4/WebM으로 뽑아 유튜브 인트로, 인스타 릴스, 카카오 채널에 재사용

## 1. 목표와 성공 기준

| 항목 | 기준 |
|---|---|
| 목표 | 첫 화면에서 "하나의 주제로 연결된 오감놀이"를 움직임으로 보여주고, 상담 버튼으로 시선을 모은다 |

## 4. 장면 구성 (7초 타임라인)

화면 구성은 지금과 같습니다. **왼쪽 문구 영역, 오른쪽 캐릭터 영역(노란 덩어리)**. 모션은 이 구조 위에서만 움직입니다. 단, B 영상은 가로(16:9) 단독 화면으로 다시 배치합니다.

| 시간(초) | 장면 | 동작 | 사용 소재 | 세부 값 |
|---|---|---|---|---|
| 0.0 ~ 1.0 | **1. 와플 격자** | 크림 배경 위에 와플 격자 무늬가 **선으로 그려짐**(위→아래, 왼→오른). 선 색 `#FBC54B`, 투명도 35%, 선 굵기 2px, 격자 칸 48px | 코드로 그림(SVG) | 선 그리기 방식(`stroke-dashoffset`), 1.0초, ease-out |
| 0.6 ~ 1.6 | **2. 로고 팝업** | 로고가 **작게(0.6배)에서 1.0배로** 튀어나오며 약간 넘쳤다 돌아옴(1.08배→1.0). 직후 별 입자 8개가 퍼짐 | `logo.png` + 코드 입자 | 0.7초, 바운스 이징. 입자 색은 `#FBC54B`, `#FF5800`, `#9FDCC4`, 크기 6~10px, 0.6초 후 사라짐 |
| 1.4 ~ 3.0 | **3. 캐릭터 4명 낙하** | 와플이 → 두근이 → 몽글이 → 또또 순서로 **위에서 떨어져** 바닥에서 **살짝 눌렸다(세로 0.92배) 펴짐**. 각 0.5초, 간격 0.25초 | 4명 이미지 | 낙하 거리 120px, 착지 후 위아래 4px 흔들림. 등장 후 각자 **다른 주기**(5.2~6.8초)로 둥실거림 |
| 2.6 ~ 4.4 | **4. 제목 글자 모션** | "북적이지 않아서," → "아이가 머무는 오감놀이" 두 줄이 **글자 단위로 통통 올라옴**. 글자 간격 0.03초. "오감놀이" 아래에 **밑줄이 손으로 긋듯 그려짐** | 글자(HTML) + 밑줄 SVG | 각 글자 0.5초, 24px 아래에서 올라옴(위치와 투명도만). 밑줄 색 `#FF5800`, 두께 6px, 0.6초 |
| 4.0 ~ 5.6 | **5. 주제 연결** | 노란 덩어리 **안에서 시즌 사진이 3장 바뀜**(감 수확 → 붕어빵 → 눈 내리는 크리스마스). 사진 1장 0.5초 노출, 크로스페이드 0.4초. 덩어리 가장자리는 모양이 부드럽게 변함 | 시즌 사진 3장 | 덩어리 마스크 안에서만 보이게 함. 마지막은 와플이로 돌아옴 |
| 5.4 ~ 7.0 | **6. 마무리** | 부제와 칩 3개가 순서대로 나타나고 **카카오톡 상담하기 버튼**이 마지막에 톡 나타남. 버튼은 이후 5초 간격으로 **살짝 반짝임 1회**(눈에 거슬리지 않게) | 기존 부제, 칩, 버튼 | 각 0.4초 간격 0.12초. 버튼 등장 후 모션은 멈춤 |

**도입 이후**: 지금 사이트의 상시 움직임(배경 덩어리 떠다님, 와플이와 칩 둥실거림, 스크롤 화살표)을 그대로 유지합니다.

## 5. A. 홈페이지 코드 모션 구현 지시

**기술 방식**
- 화면이 가벼운 **위치(translate), 크기(scale), 투명도(opacity)** 만 움직입니다. 가로세로 크기(width/height)나 위치 속성(top/left)은 움직이지 않습니다.
- 라이브러리 없이 **CSS 애니메이션과 Web Animations API**로 만듭니다. 추가가 필요하면 GSAP 코어(약 25KB)만 허용합니다.
- 장면 순서와 시간은 **한 파일(`src/hero-motion/timeline.js`)에 데이터로** 정의합니다. 이 파일을 B(Remotion)도 그대로 읽어서 같은 장면이 나오게 합니다.

**파일 구조(안)**
```
src/hero-motion/
  timeline.js        # 장면 시간, 이징, 거리 값 (A와 B 공용)
  HeroMotion.jsx     # 홈페이지용 재생 컴포넌트
  WaffleGrid.jsx     # 와플 격자 선 그리기
  Sparkles.jsx       # 별 입자
remotion/            # B용 (별도 폴더, 사이트 빌드에는 포함하지 않음)
  Root.jsx
  HeroIntro.jsx
  render.mjs
```

**동작 규칙**
1. 사이트가 미리 그려진 첫 페이지를 쓰므로(SSR), 서버가 그린 화면이 **이미 마지막 장면과 같은 정지 상태**여야 합니다. 모션은 브라우저에서만 시작합니다.
2. 도입 시작 순간 요소를 시작 상태로 되돌리면 깜빡임이 생기므로, **시작 상태 클래스를 첫 렌더 직후 한 번에** 적용합니다.
3. `prefers-reduced-motion: reduce`이면 도입을 실행하지 않습니다.
4. `sessionStorage`에 `kw-intro=1`이 있으면 도입을 건너뜁니다.
5. 도입 중 화면을 누르거나 스크롤하면 **모든 요소를 즉시 마지막 상태로** 놓습니다.
6. 도입 중에는 카카오톡 상담 버튼이 **눌러지는 상태**여야 합니다(버튼을 숨기지 않고 0.4초 만에 나타나게).
7. 휴대폰(760px 이하)은 4번과 5번 장면의 시간을 각각 0.2초씩 줄이고, 입자 수는 절반(4개)으로 합니다.
8. 시즌 사진 3장은 지금 사이트에서 이미 쓰는 같은 파일을 씁니다(추가 다운로드 없음).

## 6. B. Remotion 영상 구현 지시

**출력 규격**

| 버전 | 크기 | 길이 | 용도 | 파일 |
|---|---|---|---|---|
| 가로 | 1920×1080, 30fps | 7초 | 유튜브 인트로, 카카오 채널 | `hero-intro-16x9.mp4` |
| 세로 | 1080×1920, 30fps | 7초 | 인스타 릴스, 유튜브 쇼츠 | `hero-intro-9x16.mp4` |
| 정사각 | 1080×1080, 30fps | 7초 | 인스타 피드 | `hero-intro-1x1.mp4` |
| 홈페이지 클립(선택) | 960×540, 24fps | 5초 반복 | 첫 화면 덩어리 안 반복 영상 | `hero-loop.mp4`, `hero-loop.webm` + 포스터 `hero-loop.jpg` |

**기술 지침**
- `useCurrentFrame()`과 `interpolate()`, `spring()`으로 프레임마다 값을 계산합니다. `timeline.js`의 값을 그대로 읽습니다.
- 이징은 `Easing.bezier(.22,.8,.32,1)`(기본), `Easing.bezier(.34,1.4,.5,1)`(바운스)로 사이트와 같게 합니다.
- 글꼴은 사이트의 Nanum Square Round와 Kreon 파일을 그대로 불러옵니다.
- 홈페이지용 클립은 **소리 없음**, H.264(MP4) 약 900KB, VP9(WebM) 약 700KB를 목표로 합니다. 소리가 필요한 홍보용 파일은 별도로 음악을 입힙니다.
- 영상 클립을 쓰는 경우(§7)는 `<OffthreadVideo>`로 가져옵니다.

## 7. 유튜브 영상 클립 활용 (선택, 5번 장면 대체)

시즌 사진 대신 **대표님 채널의 영상 클립**을 덩어리 안에 넣을 수 있습니다.

- **쓸 수 있는 영상**: 키즈와플 채널 영상만. 원본 파일이나 유튜브 스튜디오에서 직접 내려받은 파일을 사용합니다.
- **구간**: 5~8초, 캐릭터가 크게 나오는 밝은 장면.
- **가공**: 소리 제거, 720p, 크기 960×540 이내로 자르고, 덩어리 모양 안에 넣습니다. MP4+WebM+포스터 사진.
- **안전장치**: 영상이 안 뜨는 기기에서는 포스터 사진만 보이게 합니다.
- **권리 확인**: 영상 속 노래나 배경음악의 사용 권리를 확인합니다(소리 없이 쓰더라도).

## 8. 검수 항목 (모두 통과해야 배포)

**기능**
- [ ] 컴퓨터(1440px, 1100px)와 휴대폰(390px, 360px)에서 장면 1~6이 순서대로 재생됨
- [ ] 도입 후 기존 둥실거림이 이어짐
- [ ] 화면 누름과 스크롤로 건너뛰기 작동
- [ ] 새로고침해도 도입이 다시 나오지 않음(같은 방문 안에서)
- [ ] "움직임 줄이기" 설정에서 정지 화면만 나옴
- [ ] 자바스크립트가 꺼진 상태에서도 제목, 버튼이 보임

**성능**
- [ ] 첫 화면이 뜨는 시간이 도입 전보다 **0.3초 이상 늦어지지 않음**
- [ ] 가로 스크롤이 생기지 않음(390px에서 폭 390px)
- [ ] 콘솔 오류 없음, 미리 그린 화면과 완성 화면 사이에 깜빡임 없음
- [ ] 카카오톡 상담 버튼이 도입 중에도 눌림

**검색(SEO)**
- [ ] 제목(h1), 미리 그린 본문 글자가 지금처럼 첫 페이지 파일에 그대로 있음
- [ ] 영상과 이미지에 설명 글자(alt)가 있음

**브랜드**
- [ ] 색, 글꼴이 §2와 같음
- [ ] 캐릭터가 늘어나거나 찌그러지지 않음(눌림은 세로 0.92배까지만)

## 9. 작업 순서와 결정할 것

**순서**
1. 장면 시간표(`timeline.js`)와 정지 화면(마지막 장면) 확정
2. A: 홈페이지 코드 모션 → 컴퓨터와 휴대폰 확인 → 배포
3. B: 같은 시간표로 Remotion 영상 3종 제작 → 용량 확인
4. (선택) 유튜브 영상 클립 반영

**대표님이 정해 주실 것**
1. 5번 장면에 쓸 소재: **시즌 사진** vs **유튜브 영상 클립** (영상이면 파일 전달 필요)
2. 도입 장면 길이: **7초(권장)** / 5초(짧게)
3. 도입 재생 횟수: **방문당 1회(권장)** / 매번
4. 와플 격자 무늬(장면 1)를 넣을지 여부
5. B 영상의 세로, 정사각 버전이 필요한지

**제약과 위험**
- 캐릭터 팔다리와 표정 연기는 **불가**(이미지 한 장). 필요하면 레이어를 나눈 원본이나 영상 생성이 따로 필요합니다.
- 로고는 한 덩어리라 글자 단위 모션이 안 됩니다. 필요하면 벡터 로고 원본이 필요합니다.
- 7초 도입은 **재방문자에게는 불편할 수 있어** 방문당 1회와 건너뛰기를 필수로 합니다.

## 10. Claude(Opus)에게 그대로 붙여넣을 지시 문구

```
키즈와플 홈페이지(저장소 kidswaffle/kidswaffle-homepage) 첫 화면에 7초 도입 모션을 만들어줘.
기준 문서: docs/hero-motion-brief.md (이 문서)를 정확히 따를 것.

1) src/hero-motion/timeline.js에 장면 1~6의 시간, 이징, 거리를 데이터로 정의.
2) A: HeroMotion.jsx로 홈페이지에 적용. translate/scale/opacity만 사용, 라이브러리 없이 CSS/WAAPI.
   - 도입은 방문당 1회(sessionStorage), 누르거나 스크롤하면 즉시 마지막 상태.
```
